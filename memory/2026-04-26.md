## 踩坑：Hermes 启动 UnicodeEncodeError
- 坑：hermes gateway run 在 exec 环境下因 GBK 编码无法输出 emoji（❌ \u274c），导致 `UnicodeEncodeError: 'gbk' codec can't encode character` 直接崩溃退出
- 绕法：启动时设 `PYTHONIOENCODING=utf-8` + `chcp 65001`，用 bat 脚本（不用 PowerShell `&` 连接，PS 会误解析）
- 另一个坑：PowerShell exec 里 `&&` 和 `&` 都被当 PS 语法解析，嵌套引号也各种出错。bat 脚本写文件再 `cmd /c "bat路径"` 或 `start` 最稳
- 记到：TOOLS.md 已有 PowerShell 陷阱条目，补充编码问题
- 批量启动脚本：`D:\OpenClaw\scripts\start_hermes.bat`
- 单独重启满满：`D:\OpenClaw\scripts\start_manman.bat`

## 踩坑：Hermes --replace 权限问题
- 坑：`--replace` 需要杀掉旧进程，但如果旧进程的 PID 文件残留且 taskkill 权限不够，会报 `Permission denied killing PID xxx. Cannot replace.` 然后退出
- 绕法：先手动 `taskkill /PID xxx /F` 杀旧进程，再删 `gateway_state.json` 和 `gateway.pid`，最后重新启动
- 另外注意：4个实例各有自己的 HERMES_HOME 目录，state 文件在各自的 HOME 下

## 踩坑：满满 HERMES_HOME 从 D:\hermes 改成 D:\MyAgents 导致钉钉消息收不到
- 坑：满满切到 D:\MyAgents 后，gateway 能启动、钉钉 Stream 能连、但 channel directory 只有0-1个 target，消息根本到不了
- 原因：D:\MyAgents 下缺少完整的状态文件（sessions、channel_directory.json 等），新 gateway 启动后无法重建正确的消息路由
- 绕法：切回 D:\hermes 作为 HERMES_HOME，3个 target 立即恢复
- 教训：HERMES_HOME 不要随便换目录，状态文件跟 HOME 强绑定，换了等于新机器人
